Good code tends to end up in the wrong places. A helper you wrote last month lives in a chat thread, a config sits in an old gist, and the button your team agreed on exists only in one repository. When a colleague asks for it, you go digging. When a coding agent needs it, the agent writes a new one from scratch, a little different each time.

Sniptide keeps that code in one place. You save it as a paste, share it with a link whose visibility, password and expiry you choose, and file the good ones in collections that Claude Code, Codex and Cursor can search and read. It runs at [app.sniptide.com](https://app.sniptide.com), and the same app runs on your own server.

## What you can do with Sniptide

- **Share code with a link you control.** A paste holds 1 to 10 files. It can be private, unlisted or public, with an optional password, an expiry from one hour to never, and burn after read for something that should be opened once.
- **Keep patterns your agent can find.** File pastes in collections, then let an agent search them over MCP, or install a collection as a skill with the CLI.
- **Hand off a project's `.env`.** Env groups store a project's variables encrypted, sync them with `sniptide env`, and share them through a password link that expires.
- **See what happened to a link.** Each paste counts views, copies and referrers in your own database, without cookies.
- **Run it yourself.** Sniptide is one Docker image next to Postgres, under AGPL-3.0.

## One pattern, from paste to agent

Say your team has settled on a button component. Here is how it becomes something your agent reuses.

<Steps>
<Step>

### Save it as a paste

Paste `Button.tsx` and its styles into a new paste. The editor sets the language from the file name and warns you if the code looks like a key.

</Step>
<Step>

### File it in a collection

Add the paste to a collection called `ui`. A collection is private to you, and its slug is the name the CLI and agents use.

</Step>
<Step>

### Connect your agent

Add the MCP server to Claude Code, then type `/mcp`, choose `sniptide` and pick **Authenticate** to sign in through the browser.

```bash title="Terminal"
claude mcp add --transport http sniptide https://app.sniptide.com/api/mcp
```

</Step>
<Step>

### Ask for it

Ask in plain language, such as "Search my Sniptide snippets for our React button and adapt it to this page." The agent calls `search_snippets`, reads the best match with `read_snippet` and works from your code instead of guessing.

</Step>
</Steps>

If you would rather keep the pattern in the repository, the CLI installs the same collection as a skill:

```bash title="Terminal"
sniptide skill ui
```

`SKILL.md` describes each paste, and the agent reads only the files it needs. A skill is a local copy, so run the command again with `--force` after the collection changes.

## How agents reach your pastes

The MCP server runs inside the app at `/api/mcp`, on the hosted app and on every self-hosted instance. An agent signs in with OAuth, or with a personal API token for clients without OAuth and for unattended jobs. A connection without a scope gets read access, and saving or editing snippets needs write access that you grant.

An agent only reaches your own live pastes. It can't see other people's pastes, your trash or your env groups, and it doesn't run code on your machine. Revoking a token or a connection cuts off access at once.

Agents that fetch a link directly can ask for Markdown with `Accept: text/markdown` and get the files as fenced code blocks, without the page around them.

## What Sniptide does not do

- **You need an account to create pastes.** Reading a public or unlisted link needs none.
- **Env values are encrypted at rest with a key the server holds.** That protects the database and its backups. Whoever runs the server can decrypt them, so Sniptide doesn't offer end-to-end encryption.
- **Collections can't be shared.** You share the pastes inside them, each with its own settings.
- **It isn't a secrets manager.** Env groups help you hand off a project's values, and they have no rotation or audit trail.

## Availability

The hosted service at app.sniptide.com is free. The app is open source under AGPL-3.0, and the CLI, SDKs and MCP package are MIT. To self-host, you need Docker, Postgres 17 and an HTTPS domain, and the [self-hosting guide](https://docs.sniptide.com/self-hosting) covers the install script, Docker Compose and Coolify.
