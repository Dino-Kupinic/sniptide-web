Good code tends to end up in the wrong places. A helper you wrote last month lives in a chat thread, a config sits in an old gist, and the button your team agreed on exists in one repository. When a colleague asks for it, you go digging. When a coding agent needs it, the agent writes a new one from scratch, a little different each time.

Sniptide keeps that code in one place. You save it as a paste, share it with a link whose visibility, password and expiry you choose, and file the good ones in collections that Claude Code, Codex and Cursor can search and read.

## What you can do with Sniptide

- **Share code with a link you control.** A paste holds up to 10 files. Make it private, unlisted or public, add a password, let it expire, or let it burn after the first read.
- **Keep patterns your agent can find.** File pastes in collections, then let an agent search them over MCP, or install a collection as a skill with the CLI.
- **Hand off a project's `.env`.** Env groups store a project's variables encrypted, sync with `sniptide env`, and share through a password link that expires.
- **See what happened to a link.** Each paste counts views, copies and referrers, without cookies.

## One pattern, from paste to agent

Say your team keeps a retry helper and a debounce hook it reuses everywhere. Here is how they become something your agent works from.

<Steps>
<Step>

### Save them as pastes

Paste each file into a new paste. The editor sets the language from the file name and warns you when the code looks like a key.

</Step>
<Step>

### File them in a collection

Add both pastes to a collection called `snippets`. Its slug is the name the CLI and agents use.

<Figure
  src="/blog/introducing-sniptide/collection.webp"
  darkSrc="/blog/introducing-sniptide/collection-dark.webp"
  alt="The Snippets collection listing three pastes with their language, visibility, views and last update."
  caption="A collection groups related pastes. Each one keeps its own visibility, from unlisted to public."
/>

</Step>
<Step>

### Connect your agent

Add the MCP server to Claude Code, then type `/mcp`, choose `sniptide` and pick **Authenticate** to sign in through the browser.

```bash title="Terminal"
claude mcp add --transport http sniptide https://app.sniptide.com/api/mcp
```

</Step>
<Step>

### Ask for it

Ask in plain language, such as "Use the retry helper from my Sniptide snippets for this fetch call." The agent calls `search_snippets`, reads the best match with `read_snippet` and works from your code instead of guessing.

</Step>
</Steps>

Once an agent connects, the dashboard lists it with the time it last called Sniptide, and a chart shows how often your agents read from your library.

If you would rather keep the patterns in the repository, the CLI installs the same collection as a skill:

```bash title="Terminal"
sniptide skill snippets
```

`SKILL.md` describes each paste, and the agent reads only the files it needs. A skill is a local copy, so run the command again with `--force` after the collection changes.

## How agents reach your pastes

The MCP server runs inside the app at `/api/mcp`, on sniptide.com and on every self-hosted instance. An agent signs in with OAuth, or with a personal API token for unattended jobs. Read access is the default, and an agent can save or edit snippets only when you grant write access.

An agent only reaches your own pastes, and revoking a token or a connection cuts off access at once. Agents that fetch a link directly can ask for Markdown with `Accept: text/markdown` and get the files as fenced code blocks, without the page around them.

## Where it runs

Use Sniptide at [app.sniptide.com](https://app.sniptide.com), or run the same app on your own server. Self-hosting takes one command, and the [self-hosting guide](https://docs.sniptide.com/self-hosting) covers the rest.

```bash title="Terminal"
curl -fsSL https://sniptide.com/install.sh | sh
```

## Why I built Sniptide

I wasn't happy with the state of pastebins. Most of them look outdated, and they're missing features I expect from any modern tool. I also wanted one I could self-host without a weekend of setup, so the install is a single command.

And I wanted a pastebin built for the way we write code now, with agents. Your agent should be able to find the snippet you saved last week as easily as you can. That's Sniptide: a pastebin that looks good, feels polished and works for you and your agents.

[Try Sniptide](https://app.sniptide.com) with the snippet you share most often, then [connect your agent](https://docs.sniptide.com/mcp) and ask it to list your collections.
