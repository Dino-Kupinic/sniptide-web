## How the skill loads

Claude uses the description to decide when to invoke the skill and loads the body when the skill runs. The body tells Claude when to read the supporting checklist. To try it, open Claude Code at the project root and run `/review-pr` on a branch with a diff. For `/review-pr 42`, install and authenticate the GitHub CLI first, and replace `42` with an accessible pull request. [Claude Code skills](https://code.claude.com/docs/en/skills)

Where you put the folder decides who gets it:

| Scope | Path | Use it for |
| --- | --- | --- |
| Project | `.claude/skills/review-pr/SKILL.md` | Workflows for this codebase. Commit it and your team gets it. |
| Personal | `~/.claude/skills/review-pr/SKILL.md` | Your own workflows, in every project on your machine. |

The folder follows the [Agent Skills](https://agentskills.io) format. Check which frontmatter extensions and discovery paths your other clients support.

## What each part does

**name** is the command you type, `/review-pr`. Use lowercase letters, numbers and hyphens. It defaults to the folder name.

**description** is what Claude reads to decide whether to use the skill. Start with what the skill does, then say when to use it in the words people actually type: "review", "check a PR", "look over a diff". A vague description is the most common reason a skill never runs.

**argument-hint** shows the optional PR number in Claude Code. `$ARGUMENTS` gives the skill the text entered after the command. The steps define the default behavior when it is empty.

**Report format** makes the output the same every time, which matters when several people read the reviews.

**checklist.md** holds the detail. Split anything long or rarely needed into its own file and link it, so the main file stays short.

## Variant: a skill only you can start

Add `disable-model-invocation: true` for a skill with side effects, such as a release. Claude Code then requires manual invocation. The example prepares a release checklist without changing the repository.

```md title=".claude/skills/release/SKILL.md"
---
name: release
description: Prepare the version and changelog for a release.
disable-model-invocation: true
---

# Release

1. Find the previous release tag and read the changes since that tag.
2. Check which version bump the repository's release policy calls for.
3. Draft the changelog entry and list the checks required before tagging.
```

## Variant: background knowledge for some files

A skill can carry knowledge rather than a task. With `user-invocable: false` it doesn't show up as a command, and `paths` limits it to the files it is about.

```md title=".claude/skills/design-system/SKILL.md"
---
name: design-system
description: The project's UI conventions. Use when writing or changing React components or styles.
user-invocable: false
paths:
  - components/**
  - app/**/*.tsx
---

# Design system

- Use the components in `components/ui` before writing new markup.
- Colors and spacing come from the Tailwind theme. Never write hex values in components.
- Every interactive element needs a visible focus style.
```
