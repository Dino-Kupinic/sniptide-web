## How the file works

Keep the variables your app actually reads. On a fresh clone, copy the file with `cp .env.example .env`, generate the required local secret and start your app with its environment loader. Add these patterns to `.gitignore` before staging files.

```text title=".gitignore"
.env
.env.*
!.env.example
```

Confirm with `git check-ignore .env .env.production .env.local`. It should list all three. If Git already tracks a secrets file, remove it from tracking and rotate any credentials that were exposed.

## What each part does

| Part | Rule | Why |
| --- | --- | --- |
| Header comment | Says how to copy the file and what not to commit. | It is the first thing someone opens on a fresh clone. |
| Groups | One `# --- Name ---` comment per service. | Long files stay scannable, and a missing group stands out. |
| Defaults | Real values that work on a laptop, such as `localhost` URLs. | The defaults give readers a local starting point. Start any services they refer to. |
| Secrets | Left empty, with a comment saying where to get one. | Validate required values at startup and document how to obtain them. |
| Optional | Grouped last, with what happens when they are empty. | People know which blanks they can skip. |

Quote a value that contains spaces, as `EMAIL_FROM` does. Comments go on their own line, because some parsers read a `#` after a value as part of the value.

## Keep it in sync with the code

Add new variables here in the same change that reads them. In this Zod 4 example, load the environment before parsing it on the server. An empty optional DSN is accepted. A missing required secret stops startup.

```ts title="lib/env.ts"
import { z } from "zod"

const schema = z.object({
  NODE_ENV: z.enum(["development", "test", "production"]),
  APP_URL: z.url(),
  DATABASE_URL: z.url({ protocol: /^postgres(?:ql)?$/ }),
  AUTH_SECRET: z.string().min(32),
  SENTRY_DSN: z.union([z.url(), z.literal("")]).optional(),
})

const result = schema.safeParse(process.env)
if (!result.success) {
  const invalidKeys = result.error.issues.map((issue) => issue.path.join("."))
  throw new Error(`Invalid environment variables: ${invalidKeys.join(", ")}`)
}

export const env = result.data
```

## Variant: a Next.js app

Next.js loads `.env.local` and inlines `NEXT_PUBLIC_` values referenced in browser code at build time. Use that prefix only for values you can publish.

```bash title=".env.example"
# Server only
DATABASE_URL=postgres://app:app@127.0.0.1:5432/app
AUTH_SECRET=

# Public values that can appear in the browser bundle.
NEXT_PUBLIC_APP_URL=http://localhost:3000
NEXT_PUBLIC_POSTHOG_KEY=
```

Copy it with `cp .env.example .env.local` in a Next.js project.

## Share the real values

Distribute real values through your team's secret manager. If you use Sniptide, authenticate the CLI and run `sniptide env push my-app --dry-run` from the project directory to preview an upload. A real push replaces the whole env group. Run `sniptide env pull my-app` to write the group's values to a local `.env`. [Sniptide secrets setup](https://docs.sniptide.com/core-concepts/secrets)
