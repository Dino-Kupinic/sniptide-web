## Run it

Use Docker with Compose v2. Run these commands from the folder containing `compose.yaml`.

```bash title="Terminal"
docker compose up -d --wait
docker compose exec db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "SELECT 1;"'
```

With the defaults, connect from the host at `postgres://app:app@127.0.0.1:5432/app`. The SQL command should return one row with the value `1`. Update the URL if you change the credentials or host port. These defaults are for local development.

`docker compose down` stops the container and keeps the data. Adding `-v` deletes the volume too, which wipes the database.

## What each part does

| Line | What it does | When to change it |
| --- | --- | --- |
| `image: postgres:17` | Pins the major version, so an upgrade never happens by accident. | When you upgrade. Plan a major upgrade with a dump and restore or `pg_upgrade`. |
| `environment` | Creates the user, password and database on the first start. `${POSTGRES_USER:-app}` reads your `.env` and falls back to `app`. | Set real values in `.env` for anything beyond your laptop. |
| `ports` | `127.0.0.1:5432:5432` publishes the port to your machine only. A bare `5432:5432` opens it on every network interface. | Change the first `5432` if another Postgres already uses that port. |
| `pgdata` volume | Keeps the data when the container is recreated. | Rarely. |
| `healthcheck` | `pg_isready` checks TCP so the temporary socket-only server used by init scripts does not report ready. `$$` defers variable expansion to the container. | Rarely. Other services wait on it, as the next variant shows. |

For a fresh Postgres 18 database, mount its volume at `/var/lib/postgresql`. To upgrade existing data, follow the [official image's upgrade and volume guidance](https://hub.docker.com/_/postgres).

The `environment` values and init scripts apply only while the volume is empty. After the first start, rotate the role's password in Postgres and update your client configuration. Recreating the container with a different environment value leaves the original password in the database.

## Variant: with your app

Add the app as a second service. `condition: service_healthy` makes Compose start it only after Postgres passes its health check, and the app reaches the database by its service name, `db`.

```yaml title="compose.yaml"
services:
  app:
    build: .
    environment:
      DATABASE_URL: postgres://app:app@db:5432/app
    ports:
      - "3000:3000"
    depends_on:
      db:
        condition: service_healthy

  db:
    image: postgres:17
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: app
      POSTGRES_DB: app
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -h 127.0.0.1 -U app -d app"]
      interval: 5s
      timeout: 5s
      retries: 10

volumes:
  pgdata:
```

The database has no `ports` here: the app reaches it over the Compose network, and nothing outside needs to. The [Next.js Dockerfile](/templates/nextjs-dockerfile) builds a matching app image.

## Variant: with pgAdmin

Add this under `services` for local development. Set a local `PGADMIN_PASSWORD` in `.env`, then run `docker compose up -d --wait`. Sign in at http://localhost:5050 and register Postgres with host `db`, port `5432`, and the database user and password from `db`.

```yaml title="compose.yaml"
  pgadmin:
    image: dpage/pgadmin4
    environment:
      PGADMIN_DEFAULT_EMAIL: admin@example.com
      PGADMIN_DEFAULT_PASSWORD: ${PGADMIN_PASSWORD:?Set PGADMIN_PASSWORD in .env}
    ports:
      - "127.0.0.1:5050:80"
    depends_on:
      db:
        condition: service_healthy
```

## Variant: extensions on the first start

For a new volume, an init script can enable extensions. On an existing volume, run the SQL as a migration after making the extension available. To use pgvector on a fresh volume, set the image to `pgvector/pgvector:pg17` and add this mount under `services.db.volumes`. Keep the existing `pgdata` entry.

```yaml title="compose.yaml"
      - ./db/init:/docker-entrypoint-initdb.d:ro
```

Save the SQL below in `db/init/` before starting the database. The image runs the initialization files in filename order.

```sql title="db/init/01-extensions.sql"
CREATE EXTENSION IF NOT EXISTS vector;
CREATE EXTENSION IF NOT EXISTS pg_trgm;
```
